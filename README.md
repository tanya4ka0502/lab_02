# Лабораторная работа №2
## Потоковый анализатор логов (`streamstats`)

---
## Описание проекта
В рамках лабораторной работы был разработан Python-пакет **streamstats** с интерфейсом командной строки (**CLI**). Программа представляет собой потоковый анализатор файлов, который читает события из логов и формирует статистический отчёт.
Утилита поддерживает два формата входных данных: **CSV** и **JSONL**. Программа построчно валидирует каждое событие, подсчитывает статистику (общее количество, распределение по уровням и источникам, топ-5 ошибок, временные рамки) и сохраняет результат в формате **JSON**.
Интерфейс командной строки реализован с помощью библиотеки **Typer**. Для обеспечения высокой производительности и обработки файлов любого размера программа использует ленивые итераторы (генераторы) и не загружает файлы в память целиком.

## Возможности программы
## Анализ логов
Программа поддерживает чтение и обработку событий с обязательными полями:
* `timestamp` — время события (строка в формате ISO 8601).
* `level` — уровень важности (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`).
* `source` — источник события (непустая строка).
* `message` — текст сообщения (строка).
## Поддерживаемые форматы
1. **CSV** — файлы с заголовком, где названия колонок совпадают с именами обязательных полей.
2. **JSONL** — формат, где каждая строка является отдельным валидным JSON-объектом.
## Формируемая статистика
1. Общее число обработанных событий.
2. Количество событий каждого уровня.
3. Количество событий каждого источника (отсортировано по убыванию).
4. Топ-5 источников ошибок (учитываются только уровни `ERROR` и `CRITICAL`).
5. Первая и последняя временная метка среди всех событий.
6. Количество пропущенных (ошибочных) строк (при использовании специального флага).
---
## Описание алгоритма решения задачи
1. Пользователь запускает программу через команду `python -m streamstats analyze ...`, передавая список файлов и флаг формата.
2. CLI (Typer) проверяет аргументы конфигурации (поддерживается ли формат, существует ли папка для сохранения отчёта).
3. Функция `analyze()` создаёт единый объект `LogStatistics` (корзину для сбора данных).
4. Для каждого файла по очереди вызывается нужный парсер (`parse_csv` или `parse_jsonl`).
5. Парсер открывает файл и считывает его построчно с помощью цикла `for line in file`. Файл не загружается в оперативную память целиком.
6. Каждая строка передаётся во внутреннюю функцию `make_event()`, которая проверяет типы данных и преобразует строку в объект `Event`.
7. Если запись валидна, она добавляется в статистику. Если нет — программа либо падает с ошибкой, либо (при флаге `--skip-invalid`) пишет WARNING в лог и пропускает строку.
8. В конце работы функции `build_report()` и `render_json()` собирают данные из `LogStatistics` и сериализуют их в JSON-файл или выводят в консоль.

## Принятые решения при реализации проекта
Во время разработки проекта были приняты следующие решения.
## 1. Разделение программы на модули
Программа разделена на несколько файлов, чтобы каждая часть отвечала только за свою задачу.

| **Файл**        | **Назначение**                                             |
|-----------------|------------------------------------------------------------|
| `models.py`     | Описание структур данных (Event, LogStatistics, Level).    |
| `parsers.py`    | Потоковое чтение файлов и валидация полей.                 |
| `analysis.py`   | Оркестрация процесса (вызов парсеров, объединение файлов). |
| `report.py`     | Формирование и сериализация итогового отчёта.              |
| `constants.py`  | Хранение всех констант.                                    |
| `errors.py`     | Хранение сообщений об ошибках.                             |
| `__main__.py`   | Запуск программы через командную строку.                   |
## 2. Потоковое чтение (Без `read()` и `readlines()`)
Для обработки файлов размером более 500 МБ используется построчное чтение. Парсеры не используют методы `read()` или `readlines()`. Вместо этого применяется итерация по файловому объекту, что гарантирует минимальное потребление оперативной памяти.
## 3. Использование `collections.Counter`
Для подсчёта статистики по уровням и источникам используется словарь `Counter` из стандартной библиотеки. Он обеспечивает высокую скорость подсчёта.
## 4. Использование dataclasses
Модели данных (`Event` и `LogStatistics`) реализованы через декоратор @dataclass. Это избавляет от необходимости писать шаблонный код инициализации и делает структуры данных наглядными и типизированными.
## 5. Иерархия исключений и коды возврата
Создано базовое исключение `StreamStatsError` и его наследники (`InvalidEventError`, `CliConfigError`).
* При ошибках конфигурации (например, неверный формат или отсутствующий файл) программа завершается с кодом **1**.
* При встрече с битой строкой (в режиме без флага) программа завершается с кодом **2**.
* При успешной работе возвращается код **0**.
## 6. Использование абсолютных импортов
В модулях пакета используются абсолютные импорты (`from streamstats.models import ...`), что делает код более явным и упрощает процесс тестирования по сравнению с относительными импортами.

# Обработка ошибок
Программа проверяет корректность введённых данных.
Обрабатываются следующие ситуации:

| **Ошибка**                     | **Пример**                                 | **Поведение**                  |
|--------------------------------|--------------------------------------------|--------------------------------|
| Некорректный JSON              | `{"timestamp": "..."`                      | `InvalidEventError`(код 2)     |
| Неверный формат времени        | `"2024-13-45T00:00:00Z"`                   | `InvalidTimestampError`(код 2) |
| Неизвестный уровень важности   | `"level": "SUPER_INFO"`                    | `InvalidEventError`(код 2)     |
| Пустой источник                | `"source": " "`                            | `InvalidEventError`(код 2)     |
| Отсутствует обязательное поле  | В CSV или JSONL нет поля `message`         | `InvalidEventError` (код 2)    |
| Неподдерживаемый формат файла  | `--format xml`                             | `CliConfigError`(код 1)        |
| Файл не найден                 | `python -m streamstats analyze nope.jsonl` | `FileNotFoundError`(код 1)     |
| Неверный путь для сохранения   | `--output /nonexistent_dir/report.json`    | `CliConfigError`(код 1)        |
При возникновении ошибки программа завершается с соответствующим кодом.

## Описание файлов проекта
### `models.py`
Содержит перечисление `Level`, модель одного события `Event` и аккумулятор статистики `LogStatistics` с методом `add()`.
### `parsers.py`
Содержит функции `parse_csv()` и `parse_jsonl()`. Они читают файлы построчно, вызывают валидатор `make_event()` и обрабатывают ошибки в зависимости от флага `skip_invalid`.
### `analysis.py`
Содержит функцию `analyze()`, которая создаёт объект `LogStatistics`, перебирает входные файлы и вызывает для них соответствующие парсеры.
### `report.py`
Преобразует внутренний объект `LogStatistics` в словарь, вычисляет Топ-5 ошибок и сериализует данные в JSON с помощью `json.dumps()`.
### `errors.py`
Хранит иерархию исключений (`StreamStatsError`, `InvalidEventError` и др.).
### `__main__.py`
Создаёт CLI с помощью Typer. Проверяет конфигурацию, запускает анализ, перехватывает ошибки и обеспечивает правильные коды возврата (0, 1, 2).
### `tests/`
Содержит unit-тесты для парсеров и моделей, а также integration-тесты для CLI.

## Примеры работы программы
### Анализ JSONL-файла
```bash
python -m streamstats analyze app.jsonl --format jsonl
```
**Вывод (stdout)**
```json
{
  "total": 1500,
  "skipped": 0,
  "files": ["app.jsonl"],
  "by_level": {
    "DEBUG": 0,
    "INFO": 1200,
    "WARNING": 150,
    "ERROR": 145,
    "CRITICAL": 5
  },
  "by_source": {
    "api": 1000,
    "db": 300,
    "cache": 200
  },
  "top_error_sources": [
    {"source": "db", "count": 120},
    {"source": "api", "count": 30}
  ],
  "first_timestamp": "2024-01-01T00:00:00+00:00",
  "last_timestamp": "2024-01-31T23:59:59+00:00"
}
```
### Анализ с сохранением в файл и объединением нескольких источников
```bash
python -m streamstats analyze app.jsonl db.jsonl --format jsonl -o report.json
```
### Пропуск битых строк
```bash
python -m streamstats analyze broken.jsonl --format jsonl --skip-invalid
```

## Тестирование программы
Для проверки работы программы используются автоматические тесты библиотеки **pytest**.
Тесты проверяют:
1. Парсинг корректных CSV и JSONL файлов;
2. Обработку пустых файлов;
3. Поведение программы при встрече с битыми строками (как с флагом `--skip-invalid`, так и без него);
4. Объединение статистики из нескольких файлов;
5. Корректную обработку Unicode (кириллица, эмодзи);
6. Коды возврата CLI и запись отчёта в файл.
